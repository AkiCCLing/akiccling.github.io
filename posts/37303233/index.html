Unity 程序基础框架

单例模式

单例模式在游戏开发中的常用性体现在以下几个优点：

全局数据共享：单例模式可以提供一个全局访问点，使得不同的游戏对象可以共享相同的数据，方便实现全局数据共享。

确保唯一性：单例模式确保了在整个应用程序生命周期中只存在一个实例对象，这样可以避免出现多个实例对象导致数据不一致或冲突的问题。

方便管理资源：单例模式可以用于管理游戏中的资源，例如音频管理器、关卡管理器等，使得资源的加载、卸载和管理更加方便和高效。

方便管理对象：通过单例模式可以方便地管理游戏中的对象，例如对象池管理器、游戏状态管理器等，使得对象的创建、销毁和管理更加灵活和简单。

访问简单化：由于单例模式提供了一个全局访问点，因此可以通过简单的调用单例对象的静态方法或属性来访问和操作单例对象，使得代码更加清晰和易读。

便于扩展：单例模式可以通过继承或扩展现有的单例对象来实现新功能或修改现有功能，使得系统更加灵活和易于扩展。

对象池(Object Pool) - 知乎 (zhihu.com)

对象池，在 Unity 当中，就是利用 SetActive，激活失活对象，减少实例化新对象带来的 GC 和性能消耗。重复利用之前已经存在的对象，通过重置属性和字段，达到重置对象的效果。

公共 Mono 模块

为什么需要 Mono 公共模块？

  1. 有时候，我们需要不是 Mono 的类也开启 Unity 的回调函数。
  2. 我们希望不是 Mono 的类也可以开启协程。
  3. 不想要场景上物体脚本上的 Update 过多（由于调用 Update 是通过反射，这会造成性能消耗）。
  4. 我们希望控制物体的 Update 的调用顺序。
